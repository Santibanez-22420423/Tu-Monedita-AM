# Contributing to Tu Monedita

## Development workflow

1. Start from the `develop` branch.
2. Create a branch for each task.
3. Implement changes following the project architecture.
4. Verify that the project builds successfully.
5. Use Conventional Commits.
6. Open a pull request targeting `develop`.
7. Request at least one approval before merging.

## Branch naming

- `feature/short-description`
- `fix/short-description`
- `refactor/short-description`
- `chore/short-description`
- `docs/short-description`

## Code conventions

- All code identifiers must be in English.
- Classes and interfaces: PascalCase.
- Functions and variables: camelCase.
- Constants: UPPER_SNAKE_CASE.
- Packages: lowercase.
- Resource files: snake_case.
- Use four spaces for Kotlin indentation.

## Pull requests

- Keep changes focused on one task.
- Explain the purpose of the changes.
- Include testing or build results.
- Request a review from another team member.
- Do not push directly to protected branches.
